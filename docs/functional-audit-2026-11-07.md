# 用户端与店长端功能排查记录

日期：2026-11-07。

本轮以当前 flower-web 工作区（含已有未提交修改）为基线，检查小程序用户端、店长端的运行入口、核心流程与异常分支，并直接修复有证据的问题。后端仅核对了相关接口及店长订单权限、状态流转源码，未修改后端或管理网站，未操作真实业务数据。以下结果不代表生产环境或微信真机全功能验收完成。

## 已修复

| 问题 | 触发条件及影响 | 修复位置 |
| --- | --- | --- |
| 空接口响应导致请求无法正常结束 | 返回 null 的成功/错误响应访问 message 或 code 时抛错，Promise 可能一直等待 | src/utils/http.ts：安全读取响应体，错误统一 reject |
| 编辑资料的账户与异步隔离不完整 | 登录失效或切换账户后保留旧表单；旧读取或保存回调覆盖新状态 | src/pages/profile/index.vue：清空表单、请求版本校验、保存状态保护、卸载清理 |
| 优惠券旧响应回填 | 账户变化后，在途请求仍写入旧账户券列表 | src/pages/coupons/index.vue：同步监听 token，清空数据并使旧请求失效 |
| 店长初始化失败无法原地恢复 | 获取门店失败后刷新按钮只加载订单，没有可用门店，无法恢复 | src/pages/store-orders/index.vue：刷新重新执行身份、门店、订单完整初始化，并重置分页和加载状态 |
| 店长待付款标签误称测试单 | 真实 PENDING_PAYMENT 订单被标为“待确认测试单” | src/pages/store-orders/index.vue：显示“待付款” |
| 支付结果轮询生命周期不完整 | 页面离开后初始请求返回仍能启动轮询；慢请求期间重复轮询使旧结果持续失效 | src/pages/payment-result/index.vue：隐藏停止轮询、版本保护、不重叠请求 |
| 花礼使用说明按钮无界面反馈 | 点击仅写控制台日志 | src/pages/my/index.vue：展示与当前业务规则一致的说明弹窗 |
| 综合测试加载器中断 | import.meta 环境变量替换只命中注释中的第一次出现，实际代码仍无法在 CommonJS VM 执行 | scripts/integration-harness.cjs：全局替换并提供可控定时器用于回归 |

新增 scripts/check-failure-recovery.cjs 并接入 check:core，覆盖空响应、资料并发及切换账户、门店失败重试、支付轮询隐藏及慢请求、卡包旧响应隔离、说明弹窗。
